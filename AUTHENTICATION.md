# Authentication and Credential Handling

## Executive summary

This repository does **not** implement application authentication. It is a
collection of local Streamlit data-science demonstrations, not a multi-user
service. There is no login page, user database, authorization middleware,
OAuth/OIDC integration, API backend, or protected endpoint.

## Components

The runtime has three relevant layers:

1. `run_app.py` lists the numbered projects and launches the selected
   Streamlit app as a local subprocess.
2. Each `*/app.py` file is a self-contained Streamlit UI that generates or
   processes synthetic/local data in the Python process.
3. `shared/ui.py` configures the page and sidebar branding; `shared/common.py`
   contains reusable metrics and random-seeding helpers.

None of these components authenticates a person or calls an external service.
The dependencies in `requirements.txt` are Streamlit, NumPy, pandas, SciPy,
and scikit-learn; there is no authentication or token library.

## Request and execution flow

When a user starts the project, the flow is:

```text
shell -> run_app.py -> streamlit run <selected>/app.py
                  -> Streamlit serves the local UI
                  -> app computes synthetic/local results and renders them
```

The browser connects to the local Streamlit server. A request is handled by
Streamlit and routed to the selected app; the app does not first validate an
identity, session token, cookie, JWT, or bearer header. There are no repository
routes such as `/login`, `/oauth/callback`, or `/api/*`.

## Credentials and tokens

- No passwords, API keys, OAuth client secrets, access tokens, refresh tokens,
  JWTs, cookies, or authorization headers are read or generated by the code.
- No environment variables or `.env` files are required.
- The applications use deterministic synthetic data and do not require
  external data-provider credentials.
- `st.session_state` in `00_dynamic_todo_workspace/app.py` stores that app's
  in-memory todo list for the current Streamlit session. It is UI state, not an
  authentication session and contains no credential.
- The JSON download in that app exports todo data only; it is not a token or
  identity artifact.

## Security boundary

This project should be treated as a local educational application. If it is
deployed publicly, Streamlit's deployment/network access controls or an
authenticated reverse proxy must provide the access boundary; this codebase
does not provide one. Do not add real secrets to source control. If a future
experiment needs credentials, load them from the deployment secret manager or
environment at runtime, keep them out of logs and downloads, and add an
explicit authentication design before exposing the app to multiple users.

## Evidence in the source

The conclusion above is based on the current source tree:

- `run_app.py` only launches a selected Streamlit app.
- `shared/ui.py` only sets page configuration and sidebar text.
- The 16 application files import Streamlit/data-science libraries and perform
  local computations.
- `requirements.txt` contains no auth, OAuth, JWT, database, or HTTP-client
  dependency.
- A repository-wide source scan found no login, OAuth, JWT, cookie, bearer,
  password, API-key, secret, or environment-credential handling.
